# SSE 非 RAG 压测探索报告：DeepSeek

日期：2026-08-06

## 实验范围

本轮复现上一轮负载，只压认证后的 `/api/chat/stream`，固定普通聊天提示词，
不进入教学设计、RAG、附件或产物分支。主模型配置为
`MODEL=deepseek-v4-flash`、`BASE_URL=https://api.deepseek.com`。
每条请求必须收到 `metadata`、至少一个 `token` 和最终 `done`，并且不能出现
`error`，才算完整成功。认证请求不计入正式指标。

这是单实例 Windows 宿主机、真实模型 HTTP-SSE 实验，不是生产流量或 SLA；RAG
相关实验按要求未做。辅助模型配置未单独归一化，因此本轮更准确地说是“主模型
切换到 DeepSeek”的对照，而不是所有模型调用都严格只走 DeepSeek。

4 路两轮合计 44 次请求、0 次失败；8 路成功完成 42/60 条流。8 路失败主要表现为
`metadata=True, token=False, done=True, error=True`，错误正文没有持久化，因此仍
不能仅凭本轮结果判断是 DeepSeek 上游限制、辅助模型调用还是后端异常。

## 与上一轮阿里云主模型对比

| 并发 | DeepSeek 失败率 | 上一轮失败率 |
| ---: | ---: | ---: |
| 1 | 0% | 0% |
| 2 | 0% | 0% |
| 4（第一次） | 0% | 11.11% |
| 4（重复） | 0% | 0% |
| 8 | 30.0% | 78.57% |

在相同负载形态下，切换主模型后 4 路本轮未出现失败，8 路失败率从 78.57% 降至
30.0%，说明上一轮确实很可能受到模型供应商/上游容量影响；但由于本轮 8 路仍有
明显失败，且辅助模型配置没有完全统一，不能把改善全部归因于 DeepSeek，也不能
宣称单实例已稳定支撑 8 路。

压测结束时后端进程工作集约 379.91MB、私有内存约 735.17MB；这是单次结束快照，
不是峰值采样。

## 结论

DeepSeek 主模型下，1～4 路在本轮短时窗口中均未出现完整流失败，8 路仍出现 30%
失败率。相较上一轮阿里云主模型，稳定性明显改善，但当前证据仍只能标记为
`exploratory`，不晋升为正式 baseline，也不直接写入简历。

## 后续门禁

1. 对 1/2/4/8 路各重复至少 3 个 5 分钟窗口；
2. 将 `error` 事件做脱敏分类并单独统计；
3. 统一主模型、结构化模型和小模型的供应商配置，再做严格 A/B；
4. 增加 Mock LLM 控制组，分离服务自身容量与上游模型容量；
5. 对后端 CPU、工作集、连接池和事件循环做 1 秒采样；
6. 只有重复实验稳定、错误归因闭环后，才生成 `baselines/` 正式证据并修改 `resume.md`。

本轮后续已追加一组错误原因诊断实验，详见[诊断报告](../sse-error-diagnostics-deepseek-2026-08-06/report.md)。
