# SmartClass 上下文压缩 A/B 实验报告

日期：2026-07-31

正式证据：[`baselines/context-compression-ab-2026-07-31/`](./baselines/context-compression-ab-2026-07-31/)

## 实验目标

验证 SmartClass 生产上下文压缩入口在长程备课线程中的收益与代价：

- A 组关闭压缩，B 组开启压缩；
- 比较 30、50、100 轮时的累计主链路 Prompt、最终上下文大小和消息数；
- 将压缩模型的 Prompt 与摘要开销计入净 Token 收益；
- 检查历史事实、结构化状态和近期 6 轮原始消息是否保留；
- 记录真实压缩模型的成功率和端到端延迟。

## 实验设计

- 对话：固定合成的八年级数学备课线程，主 Agent 回复使用确定性 fixture；
- 压缩入口：直接调用生产 `compress_state_messages()`，不是另写模拟压缩器；
- B 组重复：3 条独立线程，每条连续运行 100 轮，并在 30/50/100 轮取快照；
- 真实模型：`qwen3.7-flash-2026-07-15`，仅用于上下文摘要；
- 压缩配置：估算 Token 达 6,000 时触发，保留近期 6 轮，摘要上限 800；
- Token 口径：Qwen 未提供可用的本地 tokenizer，因此沿用生产 `estimate_message_tokens`
  的字符数/4回退估算；压缩输入和摘要输出采用同一口径。

运行命令：

```powershell
cd backend
python -m tests.benchmarks.context_compression_ab `
  --turns 30 50 100 `
  --repeats 3 `
  --trigger-tokens 6000 `
  --keep-recent-turns 6 `
  --max-output-tokens 800 `
  --max-preface-chars 6000 `
  --promote-baseline context-compression-ab-2026-07-31
```

## 正式结果

| 对话轮数 | A 累计 Prompt 估算 | B 累计 Prompt 估算 | 主链路削减 | 计入压缩开销后净削减 | 最终上下文削减 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 30 | 124,518 | 92,357 | 25.83% | **21.17%** | 47.78% |
| 50 | 347,748 | 180,348 | 48.14% | **43.18%** | 84.61% |
| 100 | 1,396,699 | 376,850 | 73.02% | **70.55%** | 84.32% |

正式运行共有 18 次真实模型压缩，18/18 成功；端到端压缩延迟 p50 为 21.28 秒，
p95 为 25.40 秒。结构化状态、权威业务字段和近期 6 轮原始消息的保留率均为 100%。
经历多次递归压缩后，预定义历史事实保留率为 91.67%。

## 质量门禁与测量修复

首次正式尝试出现 1 次 30 秒远端超时。生产逻辑按设计保留完整原上下文，并在下一轮重试成功；
但实验审计发现旧脚本没有把失败尝试的延迟和输入开销计入净收益，因此该结果被门禁拒绝晋升。

随后补充了以下测量约束并重新运行：

- 所有成功和失败尝试都计入压缩延迟；
- 失败尝试的输入 Prompt 也计入 Token 开销；
- 失败前后对完整消息状态做 SHA-256 一致性检查；
- 嵌套的 30/50/100 轮快照不在整体延迟样本中重复计数；
- 晋升要求失败回退 100%、结构化状态与近期消息 100% 保留、历史事实至少 90%，
  且 50/100 轮净 Token 削减为正。

修复后的正式基线通过全部门禁。原始逐次结果保存在 Git 忽略目录，
公开 baseline 只包含聚合数据、实验配置、指纹和限制说明。

## 结论与限制

该策略的收益随线程增长明显扩大：30 轮已覆盖压缩额外开销，100 轮净估算 Token 削减达到 70.55%。
代价是一次压缩会增加约 21–25 秒远端模型耗时，后续可继续尝试异步压缩、更小摘要模型或更短 Prompt。

这是固定合成负载的 benchmark，不代表真实生产流量；Token 是生产回退估算值，不是供应商账单值。
因此简历使用“合成长对话 A/B”“按生产估算口径”等限定词，不将其表述为线上成本节约。
